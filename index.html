🎯 El problema

        
Una empresa de aparcamientos quiere evaluar si una aplicación de visión por computador podría leer matrículas en imágenes de su banco de pruebas para agilizar el registro de entradas y salidas. ✏️ Completad con vuestras palabras: para quién es, qué necesidad resuelve y qué NO pretende hacer.

⚠️ Riesgos y límites

          
    
            
  • Privacidad: una matrícula es un dato personal indirecto. Solo imágenes ficticias o de banco de pruebas, sin personas identificables.
    • 
            
  • Retención mínima: se guarda el resultado, no la imagen; borrado tras un plazo corto.
    • 
            
  • Errores de lectura: confusiones 0/O, 8/B, suciedad, noche, ángulo… → umbral de confianza + revisión.
    • 
            
  • ✏️ Añadid algún límite más (p. ej. matrículas extranjeras, sesgo del dataset).
    • 
          

        

        

          
🧑‍⚖️ Qué sigue siendo humano

          
    
            
  • Cualquier cobro, sanción o denegación de acceso basada en la lectura.
    • 
            
  • Validar lecturas con confianza baja o imágenes no válidas.
    • 
            
  • Decidir qué datos se guardan y durante cuánto tiempo.

2.5 · Decisiones

      

        

          🖥️ Lenguaje principal · Aplicación
          
JavaScript (Node.js + HTML/CSS)

          
✏️ Borrador — Mismo lenguaje en navegador y servidor, gran ecosistema web (Express, APIs REST), fácil integración con bases de datos y despliegue sencillo.

        

        

          🤖 Lenguaje principal · IA
          
Python

          
✏️ Borrador — Ecosistema de visión y deep learning (OpenCV, PyTorch, YOLO, OCR), modelos preentrenados reutilizables y notebooks para documentar.

        

      

      

        
🔀 ¿Por qué dos lenguajes distintos?

        
✏️ La interfaz y la lógica web se benefician de JavaScript, mientras que la IA depende de librerías que están en Python. Se conectan mediante una API (el servicio de IA en Python recibe la imagen y devuelve un JSON). Alternativa válida: toda la app en Python (FastAPI/Flask) con un front mínimo en HTML/JS — decidid y justificad.
